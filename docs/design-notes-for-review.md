## Open items carried from Plans 1 and 2

- srclight-style flat packages: one directory holds the whole package, so the directory split cannot divide it; communities
  there need a graph split.
- The Perl grammar resolves only via Cargo.lock (the upstream version was yanked).
- `parse().unwrap_or` fallbacks in the store hide malformed stored values instead of reporting them.
- The repo head is not refreshed on each run.
- git calls could set `GIT_OPTIONAL_LOCKS=0` and disable fsmonitor.
- `check` does not report leftover `running` runs.
- History was squashed into one clean root commit on 2026-10-12; the old history branch was deleted the same day.
- Non-code files become symbols: the taken parser layer records a Dockerfile `FROM python:3.12-slim` as a `class` (seen on the srclight proof vault, 2026-10-12). Decide whether config/infra languages (Dockerfile, YAML, TOML, HCL, CSS, HTML) should produce symbols at all, or only file nodes, so communities, search and `map` are not polluted.
- Wording in generated descriptions is not pluralised ("1 claims", "1 files"); cosmetic, template-level.

Task 6 (2026-10-12): `typed_receiver_method` resolves `r.m()` from a type declared in the caller (`Square r`, `r: Square`), not inferred. The vendored Java extractor reports no call site for `new T()`; Rust integration tests that name the package crate (`use demo::util::x`) get no `imports` edge (needs Cargo.toml crate-name resolution). Both are recorded in fixtures/{java,rust}/NOTES.md.

## Plan 6 A2 (Go: receivers, packages, qualified calls) — 2026-10-13

| decision or known limit | alternative | why | who it hurts |
|---|---|---|---|
| in Go the PACKAGE (a directory plus its package clause; `foo_test` is its own package) is the unit of "same module". The invariant "a module-table reference binds only an imported or same-file function" is read as: for Go, an unqualified call binds to a function of the same package, 1.0, because the package table is the evidence (the language gives every file of the package the same scope). Table references (`refs`) are unchanged: same file or import only | same file only | the gold shows unqualified calls into sibling files (`unsyncedConfigAccess` in `caddy.go` → `admin.go`) | a name defined twice in a package (build-tag variants `x_unix.go`/`x_windows.go`) binds NOTHING |
| a Go call is decided by `go_ctx.rs` and never falls back to a name guess: bound at 1.0 through the package table or a DECLARED type (`var x T`, `x := T{}`, `x := &T{}`, `x := NewT()` with a declared result, `new(T)`, `x.(T)`, parameters, the method receiver itself, struct fields along a path `a.b.m()`, embedded types up to 3 deep), else no edge. The old 0.5 name-only edge no longer exists for Go (caddy: 0 Go calls below 1.0) | keep the 0.5 guess | the guess was the only way an unknown receiver bound; Review Focus 2 forbids it | a call on a value of a type we cannot read (a result of a method, a range variable, a generic instantiation `F[int](x)`, a function literal call) binds nothing |
| an INTERFACE-typed receiver (a parameter typed by an `interface` declaration, or an embedded interface that could also supply the method) binds nothing; so does a receiver whose type is declared twice | bind the sole implementation | interface vs implementation ambiguity (Review Focus 2) | calls through an interface are never edges |
| a type conversion `T(x)` is not a call (a name that is a type of the package, or a local variable, binds nothing); a struct literal `T{}` is not a call; `defer f()` and `go f()` ARE calls (the vendored `spawns` site is matched to the real call expression by line and callee) | an edge to the type | the readers marked conversions ambiguous | `pkg.T(x)` conversions of imported types also bind nothing |
